# 同频 · 我们的小世界（公开只读版）

保留原情侣空间的黑白手绘、米白纸面界面与六个栏目，发布到 GitHub Pages。无需服务器、数据库、邮箱登录或付费的 Render 服务；访客打开固定网址即可浏览。

**线上地址：** https://yuliye0409-hue.github.io/tongpin-showcase/

## 现在可以做什么

- 浏览日常、相册、心愿和纪念日；放大照片、拆开信件。
- 在电脑、手机和平板上浏览；支持数字键 1–6 导航、原生弹窗及减少动态效果。
- 复制固定网站链接，分享给其他人查看。
- 游戏栏目保留原界面的只读预览；当前没有跨设备在线游戏。

**当前人物、日期、文字和照片均为原项目的示例内容，不是站点所有者的真实私人记录。** 页面也会显示示例标记。没有从私有数据库导出内容。原来的完整应用继续保留在私有仓库，不随本仓库公开。

## 更新文字和照片

1. 编辑 `content.json`：`members` 是展示昵称，`since` 是开始日期，`records` 存放日常、照片、信件，`wishes` 是心愿，`anniversaries` 是纪念日。
2. 图片放在 `assets/` 中，在记录的 `media` 中填写相对路径，例如 `assets/coast.jpg`。手写信也可指定手写图片的相对路径。不要使用本地电脑路径。
3. 将 `updated` 改为本次更新的日期。`records` 按文件顺序展示，建议最新记录放在前面。每条记录使用不同的 `id`。
4. 确认所选内容愿意公开后再提交。替换成自己的内容后，将 `sample` 改为 `false`。
5. 将修改推送到 `main`。GitHub Pages 重新发布成功后，刷新原网址即可查看，不需要换分享链接。

访客不能上传、修改、点赞保存、勾选心愿或共同管理。网站没有把本机存储伪装成多人同步。没有登录、邮件提醒或后台写入 API，也没有拷贝原应用的 Service Worker，避免旧缓存妨碍内容更新。

## 公开范围

这是公开网站和公开仓库，任何人都可能看到网页、内容文件和图片。没有“仅两个人访问”的保护；不保证网址无法被搜索或转发。不要提交 `.env`、API 密钥、数据库、验证码、私人分享令牌或不愿公开的信件、照片。

从公开内容中移除文件，并不保证 Git 历史、他人下载的文件或缓存同时消失。不要把不愿公开的材料先传上来再删除。

## 发布设置

仓库 Settings → Pages：选择 **Deploy from a branch**，分支 `main`、目录 `/(root)`。项目中所有资源都使用相对地址，支持 `/tongpin-showcase/` 子路径与 `#photo` 等栏目链接。

本仓库没有 Actions 构建脚本，不需要安装生产依赖。只发布根目录静态文件；不要把原应用的 `server.mjs`、`.data/` 或环境配置拷贝进来。

## 本地预览与检查

需要 Node.js 24 或更新版本。语法及内容检查：

```powershell
node --check app.js
node --test tests/content.test.mjs
```

浏览器检查脚本使用已有的 Playwright 与 Edge，仅用于开发测试，不是网站依赖：

```powershell
$env:PLAYWRIGHT_MODULE='你的 Playwright index.mjs 路径'
$env:BROWSER_CHANNEL='msedge'
node tests/browser-smoke.mjs
```

脚本会临时启动本地静态服务器，验证与 GitHub Pages 相同的项目子路径，覆盖手机布局、各栏目、相册、信件、分享、刷新及异常提示，完成后关闭。截图位于被忽略的 `test-results/`。
